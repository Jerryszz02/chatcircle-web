# Chat Circles 前端 UI 设计规范（V1）

> 本文档从 `docs/ChatCircle_Web_UI_Design_Spec_v1.0.docx` 中**仅提取纯前端视觉与交互部分**（设计方向、色彩、字体、间距、组件、动效、响应式、无障碍、文案语气、图表样式），作为 `frontend/` 实现的统一依据。凡涉及业务流程、信息架构、状态机、权限、页面清单的内容，**一律以 PRD v0.3 与 `docs/planning/` 现有文档为准**，本文不重复、不覆盖。

## 文档目的

- 为三端界面（参与者端、机构管理后台、超级管理员后台）提供一套可执行的设计系统：token、组件规则、响应式与无障碍基线。

- 防止界面退化为「通用蓝白后台」或「AI 紫色科技感」（设计稿附录 C 明确否定）。

### 已确认的设计方向（设计稿「文档说明」）

- 参与者端：方向 A「温暖社会创新风」——暖白背景、深青绿品牌色、柔和圆角、低认知负担、移动优先。
- 机构/超级管理员后台：方向 C「极简公益科技风」——白底为主、克制装饰、严格网格、桌面优先、高密度表格。
- 两端共享同一设计系统，视觉母题为**圆、圆环、重叠与连接**（对应 Circle、对话与关系网络）。
- 明确否定：卡通吉祥物、糖果色、游戏化积分/徽章/排行榜、大面积紫色渐变、玻璃拟态、通用蓝白企业模板。

### 使用规则

- 暖黄（Accent）只做强调色，不做大面积背景。
- **状态色必须与品牌色区分**，禁止「品牌色 = 成功状态」的语义混淆；状态同时使用文字 + 颜色 + 图标，不依赖单一颜色。
- 参与者端比例约 70% 暖白浅底 / 20% 中性 / 10% 品牌与强调；后台约 85% 白与中性，品牌色集中在主操作、选中态、链接与关键指标。
- 禁止同一页面出现多个高饱和度装饰色块。

## 字体与排版

| 层级 | 规格 | 用途 |
|---|---|---|
| Display | 32–40 px / 700 | 参与者端首屏标题，单页最多 1 处 |
| Page Title | 28–32 px / 700 | 页面标题 |
| Section Title | 20–24 px / 650 | 大模块标题 |
| Card Title | 16–18 px / 600 | 卡片标题 |
| Body | 14–16 px / 400 | 正文与表单 |
| Small | 12–14 px / 400 | 辅助信息、表格 |
| Label | 12–14 px / 600 | 字段标签、状态文本 |

- 中文：使用系统字体栈（`system-ui` / PingFang SC / Microsoft YaHei 等），**不自托管**中文字体——完整中文字体文件体积大，自托管对移动端首屏是负优化，系统栈对本产品已够用。
- 英文与数字：**自托管 Inter**（仅拉丁字符集，体积小）；后台数字启用等宽数字特性（`font-variant-numeric: tabular-nums`）以利表格对齐。
- 正文行高约 1.5；表格行高 40–48 px；移动端正文不低于 14 px；表单输入字号 16 px（现有实现已如此，避免 iOS/微信聚焦自动放大）。
- 避免大段居中正文、全大写英文、过度粗体。

## 图标、影像与动效

- 图标：统一使用 **Lucide**（线性、圆角端点，与设计稿风格要求吻合，按需引入体积小）；禁止混用填充与线性图标。当前页面基本未用图标，UI 迁移做到需要时再引入该依赖。
- 影像：参与者端优先真实、多元、自然互动的活动照片；圆形插画只用于登录、空状态、完成状态；后台空状态插画 160–240 px、单色或双色。
- 动效：页面进入 150–220 ms 淡入 + 4–8 px 位移；悬停 120–160 ms；弹窗/抽屉 180–240 ms（禁止弹跳与过度缩放）；成功反馈 300–500 ms 轻量圆环或勾选（不用烟花彩纸）；必须尊重 `prefers-reduced-motion`。

## 组件规范摘要

详细规则见设计稿第 07 章；以下为对现有 `shared/ui/` 组件有直接约束的要点。

- **按钮**：Primary（深青底白字，每视图区最多 1 个）/ Secondary（白底品牌色边框）/ Tertiary（文字或浅底）/ Danger（红色，不得用品牌色）/ Icon（必须配 tooltip 或文字）。桌面高 40 px、移动端主按钮 48 px、文字按钮保持 44 px 可点区域；加载时宽度不变并禁止重复提交；危险操作确认弹窗标题直接写明动作和对象。
- **表单**：标签永远在字段上方，不用占位符代替标签；必填用文字标注而非只用星号；输入后或离开字段时校验，提交时聚焦首个错误；错误文案说明问题和修复方式；草稿表单显示自动保存状态。
- **卡片**：参与者端活动卡片圆角 16 px、整体可点击但按钮保留明确标签；后台 KPI 卡片白底轻边框 + 单个强调数字，不用大面积彩底；卡片嵌套不超过两层。
- **表格**：默认行高 48 px（紧凑 40 px）；关键标识列可固定、操作列固定右侧；已应用筛选以可移除标签显示；区分「没有数据」和「筛选无结果」；复杂后台表格不强行做手机响应式，改卡片列表或要求桌面使用。
- **状态标签**：五色语义固定——绿=成功/已完成、琥珀=待处理、红=错误/未通过、蓝=处理中、灰=中性（草稿/已关闭/已归档）。
- **Toast**：仅短暂反馈、最长两行；重要结果和错误必须同时保留在页面中。
- **弹窗/抽屉/页面**：轻量确认用弹窗；对照列表查看详情用右侧抽屉；超过 6 个字段或多步骤进独立页面；有未保存内容关闭时需提示；移动端避免多层弹窗。
- **加载/空/错误**：首屏用与页面结构一致的骨架屏，不用全屏旋转图标；局部更新保留其他内容可读；空状态说明现状并给出一个下一步；系统错误给重试和错误编号，不展示堆栈；离线保留已输入内容。

## 数据可视化样式规则

适用于 M4 看板（[technical-design.md](technical-design.md)）；Impact Snapshot / Conversation Pulse / Circle Map 等品牌化表达属**后续版本**，不在 V1 实现范围。

| 图表 | 适用场景 | 规则 |
|---|---|---|
| 趋势折线 | 活动数、参与人数、完成率随时间变化 | 不超过 3 条线，时间粒度明确 |
| 漏斗 | 报名 → 通过 → 签到 → 问卷 | 同时显示数量和阶段转化率 |
| 横向条形 | 量表题分布、活动对比 | 适合长标签，按逻辑顺序排列 |
| 100% 堆叠条 | 同意/不同意分布 | 保持量表色序一致 |
| 点图/区间图 | 机构或活动间多组比较 | 优于多组柱状图 |
| 圆环图 | 仅单一完成率 | 不用于多分类或精确比较 |

所有指标必须显示口径、时间范围与样本量；小样本显示「样本不足」而非看似精确的数字；无可靠对比基准时不显示上升箭头。

## 响应式与移动端

| 断点 | 范围 | 策略 |
|---|---|---|
| Mobile | 320–767 px | 参与者端主要目标；单列、底部导航、全宽主按钮 |
| Tablet | 768–1023 px | 参与者双列卡片；后台可折叠侧栏 |
| Desktop | 1024–1439 px | 后台主要目标；完整侧栏与表格 |
| Wide | ≥1440 px | 内容限最大宽度，不无限拉伸 |

移动端专项：关键操作固定在底部安全区（`env(safe-area-inset-bottom)`，现有 Modal 已实现）；日期时间优先原生控件；不得依赖 hover 才能发现操作；图标按钮需文字或辅助标签；页面无横向滚动（现有 `overflow-x: hidden` 已兜底）。

## 无障碍基线（WCAG 2.2 AA）

- 对比度：正文 ≥ 4.5:1，大字 ≥ 3:1；状态不只靠颜色传达。
- 键盘：全部流程可键盘完成，焦点顺序符合视觉顺序；保留清晰的 2 px 品牌色焦点环（现有 `:focus` outline 样式迁移时改用品牌色，不得移除）。
- 语义：标题层级、表格表头、表单标签与按钮语义正确；状态更新使用适当的 live region；错误与字段关联。
- 触控目标 ≥ 44×44 px（现有组件已满足）。
- 动效尊重 `prefers-reduced-motion`；无闪烁与快速循环动画。
- 页面设置正确 `lang`；中英文混排保持可读。

## 内容与文案语气

- 清楚：按钮用具体动作（「提交报名」「查看审核结果」），不用「确认」「继续」等模糊词。
- 尊重：未完成任务不表述为责备；中性：审核结果不暗示个人价值，解释流程而非评价人。
- 简短：参与者页面一句话一个信息；透明：说明数据用途、谁可见、保存状态和下一步。
- 具体业务文案（审核结果、签到、问卷、隐私同意等）的措辞以 PRD 口径和业务状态为准，本文只规定语气原则。

## 实现指引

1. **建立 token 层**：在 `global.css` 顶部以 CSS custom properties 定义上文全部 token（建议命名 `--cc-brand-600`、`--cc-neutral-50`、`--cc-radius-card-participant`、`--cc-space-4` 等），三端 `*.css` 只引用变量，不写死色值。
2. **迁移现有样式**：`global.css` 当前主色为通用蓝 `#1a56db`、错误色 `#d92d20`，逐组件替换为品牌 token；按钮圆角、卡片边框、焦点环颜色随之一并迁移。迁移属纯样式变更，不改组件行为。
3. **双密度落地**：参与者端（`participant.css`）用 16 px 卡片圆角、暖白 `Neutral 50` 底；后台两端（`admin.css` / `superadmin.css`）用 8–12 px 圆角、`Neutral 100` 底、白卡片。
4. **组件改造顺序**：Button → Input/表单 → Card → 状态标签 → Modal/Toast → 表格与看板指标（`.cc-metric*`）→ 骨架屏。每步对照「组件规范摘要」验收。
5. **新增能力**：骨架屏组件（替代全屏 spinner 的首屏加载）、状态标签组件（五色语义）、筛选标签——均为 `shared/ui/` 的新组件，按现有组件模式实现。
6. 样式变更后运行前端现有测试与 lint（命令见 [test-plan.md](test-plan.md)），并人工核对 320–430 px 与 1024 px 以上两端点。

## 验收标准

- 品牌一致：三端无通用蓝色残留；参与者端温暖不幼稚、后台克制专业；无紫色渐变/玻璃拟态。
- token 化：组件样式中不出现写死的品牌色/中性色 hex，全部经由 CSS 变量引用。
- 状态覆盖：核心组件具备 default/hover/disabled/loading/error 状态，且状态不只靠颜色区分。
- 响应式：参与者端页面在 320–430 px 完整可用；后台在 ≥1024 px 高效使用；无横向滚动。
- 无障碍：对比度达标、焦点环可见、触控目标 ≥44 px、表单错误与字段关联。
- 回归：现有前端测试全部通过，无组件行为变化。
