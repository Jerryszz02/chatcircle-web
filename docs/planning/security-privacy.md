# 安全与隐私（Security & Privacy）

- 项目：Chat Circles 活动管理、报名审核、签到与问卷数据平台（Empact）
- 需求基线：PRD v0.3（评审修订版，2026-08-05），对应章节：§3.2、§6.1、§6.9、§9、§10、§11、§12、§13、§16.1
- 技术基线：React 18 + Vite + TypeScript（手机优先）+ PocketBase（认证 / 业务 API / SQLite）+ Docker；正式域名 `chatcircle.empact.cn`
- 文档状态：开发前规划文档，供实现工程师作为安全相关实现契约

---

## 1. 文档目的

本文档把 PRD v0.3 中分散在 §11（隐私、安全与审计）、§6.1（账号与认证）、§6.9（记录保留与审计）、§10（统一数据导出）、§12（技术架构与部署）、§16.1（风险表）中的安全与隐私要求，收敛为实现侧可直接执行的决策与契约，覆盖：

- 数据分级与去标识化规则（普通业务数据 vs `is_sensitive` 直接身份信息）；
- 三级账号的认证与授权边界，以及机构隔离的服务端强制方式；
- 对外隐私表述口径（平台不是完全匿名系统）；
- 密码、日志、导出全链路的凭据与敏感内容保护；
- 审计日志的高风险操作清单、字段、不可变性与检索权限；
- 登录限流、会话策略、导出文件保护、HTTPS 与部署安全；
- 威胁与缓解对照表。

本文档不重复 PRD 的业务流程描述，只定义实现安全需求所需的判断依据、输入输出与验收方式。

## 2. 适用范围

- 适用于全部三个前端入口（参与者 Web、管理员 Web、超级管理 Web）、PocketBase/API 后端、SQLite 数据库、导出文件存储、备份任务与 Docker 部署链路。
- 适用于 V1 全部里程碑 M0~M5：M0 的机构隔离原型与三级账号是安全地基；M4 的导出与审计、M5 的备份恢复与告警是安全验收重点。
- 约束对象为所有处理以下数据的代码路径：账号凭据、报名字段答案、签到记录、问卷答卷、导出文件、审计日志、备份文件。

## 4. 数据分级

### 4.1 分级模型

V1 只有两级数据分级，判断依据是字段上的 `is_sensitive` 标记，**不是字段名**：

| 级别 | 定义 | 包含内容 | 处理规则 |
| --- | --- | --- | --- |
| 普通业务数据 | 不含直接身份信息的业务记录 | 活动、报名状态、签到状态、`question_code` 非敏感题答案、看板聚合指标 | 所有管理员可按权限范围访问与普通导出 |
| 敏感数据（`is_sensitive = true`） | 可识别到自然人的直接身份信息 | 姓名、手机号等报名敏感字段答案、用户名、被标记敏感的问卷题目答案 | 仅敏感导出可包含；普通导出按标记排除或掩码 |

关键规则（PRD §9.2、§10.2、FR-EXP-002）：

- 普通导出中跨表关联一律使用 `participant_id`（系统随机生成，不含用户名或身份字段，见附录 B 命名规范），**不导出用户名**；
- 过滤依据是 `registration_field_defs.is_sensitive` 与 `survey_questions.is_sensitive` 两个标记位，实现中禁止再按「字段名叫 name/phone」之类启发式判断；
- `data_dictionary.csv` 必须包含每个字段的敏感标记，使下游分析方能复现过滤口径；
- 敏感导出 = 普通导出 + 经主动选择的个人信息字段，需二次确认并写审计（详见 §8、§10）。

### 4.2 敏感标记的设置入口

| 位置 | 谁设置 | 约束 |
| --- | --- | --- |
| 标准报名字段 | 超级管理员维护字段库时设置 | 机构只能选启用/必填，不能改字段代码、类型和敏感标记语义 |
| 机构自定义报名字段 | 机构管理员创建时设置 | 创建界面必须提供敏感标记开关，导出中单独标记 |
| 标准问卷题目 | 超级管理员维护模板时设置 | 核心锁定题的标记不可被机构修改 |
| 机构自定义问卷题目 | 机构管理员创建时设置 | 同上，必须显式设置 |

## 5. 认证与授权边界

### 5.1 三级账号模型

| 角色 | 凭据 | 数据范围 | 关键边界（PRD §3.2、附录 A） |
| --- | --- | --- | --- |
| 超级管理员 | 用户名 + 密码 | 全平台 | 全平台仅一个账号，初始部署时创建；V1 无创建/停用/更换/找回的产品界面（FR-AUTH-009） |
| 管理员 | 用户名/邮箱 + 密码，或邮箱 OTP 验证码（2026-08 后端改版） | 仅所属机构 | 必须经一次性邀请码注册（邀请码 + 用户名 + 必填邮箱 + 密码）并绑定 `organization_id`；邮箱验证与找回走 PB 内置端点，仅已验证邮箱可找回密码（未验证静默 204）；不得修改参与者账号的用户名/密码 |
| 参与者 | 用户名 + 密码（无微信/手机号/邮箱） | 仅本人相关记录 | 不能进入管理后台；不能查看他人的报名、问卷、名单或统计 |

### 5.2 授权实现契约

以下规则全部是服务端责任，前端只做展示层隐藏，不得作为权限控制（PRD §11.2、§12.2、§13）：

- **机构隔离服务端强制**：管理员身份的所有列表、详情、统计、导出查询，由后端根据登录身份注入 `organization_id` 过滤条件；客户端传入的机构 ID、筛选、URL 或 API 参数中的越权值一律忽略并返回无权限（FR-ORG-006）。所有机构业务表必须带 `organization_id` 或可经 `activity_id → activities.organization_id` 等路径可靠反查。
- **超级管理员接口单独鉴权**：超管接口不复用机构管理员的权限规则，独立鉴权；机构管理员令牌调用超管接口必须拒绝。
- **参与者无法进管理后台**：参与者令牌不具备任何管理端 API 权限；管理端路由与 API 按账号类型（集合）区分鉴权。
- **参与者账号是全平台表**：`participant_accounts` 不绑定 `organization_id`，参与者数据访问按「仅本人」过滤（`participant_id = 当前登录账号`），与机构隔离是两条独立规则，不要混用。
- **培训信息按资格可见**（2026-08 培训体系）：`trainings` 集合对参与者/匿名不可直读（无公开列表/详情）；参与者培训信息仅经白名单端点 `GET /api/cc/me/trainings` 下发，账号须存在 approved 聆听者报名（eligible），未 eligible 时列表恒空；响应不下发 `checkin_qr_token`。
- **培训签到资格口径**：自助签到与管理员补签均校验「存在 approved 聆听者报名」（账号级、全平台任一活动通用），不满足返回 `listener_not_approved`；补签候选人名单为该资格全集按参与者去重（候选人跨机构可见属设计口径——培训资格本身全平台通用，且只暴露 participant_id + username）；培训签到二维码 token 由服务端生成（同活动 `checkin_qr_token` 加固口径）。
- **无凭据重置入口（参与者）**：包括超级管理员在内，任何角色均无重置**参与者**凭据的产品入口（PRD §3.2）；参与者账号 V1 不实现账号找回/密码重置。管理员邮箱找回是 2026-08 后端改版为 `admin_accounts` 新增的能力（仅已验证邮箱放行），不影响参与者红线。

### 5.3 服务端校验的安全敏感点

以下操作除业务校验外，与安全强相关，必须在服务端事务内完成（PRD §0.1、FR-REG-005/007）：

- 报名通过、角色修改、状态回退：事务内重新校验总名额与角色名额，防止并发审核超额（AC-08）；
- 报名、签到、问卷提交接口幂等：网络重试或重复点击不得产生重复正式记录（AC-20）——这同时是数据完整性安全措施（防止刷记录）。

## 6. 隐私表述口径

平台**不是技术意义上的完全匿名系统**（PRD §11.1）。实现与文案必须统一为以下口径，禁止在 UI、导出说明或对外材料中宣称「完全匿名」：

- 倾诉者使用自定义用户名，普通分析导出去标识化（`participant_id` 关联、不含直接身份信息）；
- 但系统仍收集报名资料，平台侧能够建立账号与报名记录的关联；
- 匿名/假名化承诺主要针对倾诉者；聆听者不承诺匿名（PRD §3.1）。

注册/报名链路中向参与者展示的推荐提示语，采用 PRD §11.1 原文：

> 请创建一个不包含真实姓名、手机号或常用社交账号的用户名。系统使用该账号关联您在不同活动中的记录；普通分析和对外报告不展示姓名或联系方式。

配套约束：用户名规则 4–20 位，仅字母、数字、下划线，全局唯一且字母不区分大小写（FR-AUTH-005）；规则校验在服务端执行。

## 7. 密码与日志安全

- 密码只以不可逆安全哈希保存（FR-AUTH-004）。PocketBase 默认对密码做哈希存储，实现时不得自行引入可逆存储或明文镜像字段。
- 数据库、应用日志、审计日志、导出文件中均不得出现原密码（FR-AUTH-004 验收要点）。
- 日志不得记录：密码、完整敏感报名答案、不必要的完整问卷正文（PRD §11.2）。请求日志如需记录表单内容，按 `is_sensitive` 标记做脱敏或直接不记录值。
- 邀请码在 `admin_invites` 中存 `token_hash` 而非明文（PRD §9.1），校验时哈希比对；生成后明文仅展示一次给超级管理员。
- 邮箱验证码（OTP）与验证/找回邮件 token 由 PocketBase 内置机制生成、存储与校验（2026-08 后端改版）；应用日志、请求日志与审计 `metadata` 一律不记录其明文（同密码口径），管理员注册/邮箱相关事件的审计 metadata 也不含邮箱明文。

## 8. 审计要求

### 8.1 高风险操作清单（必须写审计）

以 PRD FR-AUD-004 与 §11.3 为准，V1 至少覆盖：

| 类别 | 审计事件 |
| --- | --- |
| 账号 | 邀请码生成、撤销、使用；账号停用；管理员邮箱验证、邮箱变更、找回密码放行/拦截（`auth.password_reset.suppressed`，2026-08 改版） |
| 活动 | 发布提交、批准、驳回、下架、名额修改、状态变更 |
| 内容推文（2026-08 改版） | 推文创建、更新、发布（置 visible）/隐藏 |
| 报名 | 审核通过、拒绝、角色修改、取消、状态回退（含前后状态） |
| 签到 | 开放、关闭、自助签到、补签、撤销 |
| 培训（2026-08 扩展） | 培训发布、关闭、签到开放/关闭、自助签到、补签、撤销 |
| 问卷 | 模板发布、活动问卷开放/结束、答卷作废 |
| 数据 | 普通导出、敏感导出、机构权限开关修改、备份（成功/失败）、恢复 |

其中以下操作除审计外还须**填写原因**：补签/撤销签到（活动与培训）、报名取消与状态回退、活动审批/驳回（原因记录于对应业务表并进入审计）。

### 8.2 审计字段与存储契约

`audit_logs` 表（PRD §9.1）：`actor_id, actor_role, organization_id, action, target, metadata, created_at`。实现要求：

| 字段 | 内容 |
| --- | --- |
| 操作者 | `actor_id` + `actor_role`（三级角色区分） |
| 机构 | `organization_id`（平台级操作可空或标记为平台） |
| 对象 | `target`（实体类型 + ID，如 `registration:reg_...`） |
| 动作 | `action`（稳定枚举值，便于检索） |
| 时间 | `created_at`，ISO 8601 并明确时区 |
| 结果 | 成功/失败（备份等任务类事件必须记录结果） |
| 原因/上下文 | `metadata`（JSON，含原因、前后状态、导出范围、是否含个人信息等） |

### 8.3 不可变性与读取权限

- 审计记录**不可由普通管理员修改或删除**（FR-AUD-002）；`audit_logs` 只对系统内部写入路径开放，不提供任何更新/删除的产品界面或普通 API。
- 读取权限（FR-AUD-005、附录 A）：机构管理员**只读检索本机构**审计日志；超级管理员**全局检索**；被审计方不可修改。参与者不可见。
- 检索维度：时间、操作者、机构、动作（FR-AUD-004）。
- 保留：默认至少 1 年（FR-AUD-003）；到期后的处置策略属「待确认」（见 §14）。

## 9. 登录限流与会话策略

| 项目 | V1 规则 | 依据 |
| --- | --- | --- |
| 登录限流 | 连续登录失败达到阈值后触发临时限制，防暴力尝试 | FR-AUTH-007、AC-21 |
| 邮件类端点限流（2026-08 改版） | request-verification / request-otp / request-password-reset 三类发信/验证码请求：per-email 3 次/小时 + per-IP 20 次/小时滑动窗口，超限返回 429 `TOO_MANY_ATTEMPTS`（mailguard.pb.js，复用 authguard 限流模式） | 2026-08 后端改版计划（PRD 外） |
| 参与者会话 | 默认保持 30 天；未主动退出且令牌有效可继续使用；主动退出立即失效 | FR-AUTH-006、§12.4 |
| 管理后台会话 | **不因「连续无操作」自动退出**；仍需具备令牌过期和主动退出机制 | §12.4 |
| 密码错误处理 | 用户名已存在时验证密码，错误密码不得创建重复账号 | FR-AUTH-001、AC-06 |

实现注意：限流需对参与者登录、管理员登录、超管登录三类入口都生效；阈值、锁定时长 PRD 未给出数值，见 §14。PocketBase 自带认证集合的令牌机制可作为会话基础，参与者 30 天有效期与管理端令牌有效期需分别配置。

## 10. 导出文件保护

依据 FR-EXP-005、§10.3、§11.2、§16.1：

- 导出 ZIP 存放于**受保护目录**（不挂在公开静态路径下），仅通过带鉴权的下载接口提供，下载前校验当前账号是否有权访问该 `export_jobs` 记录的范围与机构。
- 下载 URL **不公开、不连续可猜**（使用随机文件 ID/令牌，禁止自增序号或可推断命名）。
- 导出文件**不设置自动失效时间**；安全性由鉴权访问、敏感导出审计与机构权限开关共同保证，而非靠过期。
- `export_jobs` 记录：导出人、范围（`scope_json`）、时间、是否含个人信息（`include_pii`）、文件路径与校验信息，全部留痕（§10.3）。
- 敏感导出：主动选择 + 二次确认 + 审计；机构管理员是否可用由超级管理员按机构开关 `allow_sensitive_export` 控制，开关校验在服务端执行（FR-EXP-003、FR-ORG-005）。

## 11. HTTPS 与部署安全

- 全站 HTTPS；生产环境禁止明文 HTTP 登录（§11.2）。`chatcircle.empact.cn` 由反向代理提供 TLS（§12.1），HTTP 请求重定向到 HTTPS。
- 部署组件与数据分离：Docker 镜像与数据卷分离，SQLite 通过持久化卷与应用容器分离，升级或重建容器不得覆盖生产数据（§12.3）。
- 备份安全：数据库及上传文件每日备份、保留 30 天、至少一份在异机/异存储位置（§12.3）；备份结果（成功/失败）写审计，失败时超级管理后台显著告警（AC-23）；恢复前二次确认并写审计。
- 超级管理员账号仅初始部署时创建（FR-AUTH-009），部署脚本负责建站初始化，不提供运行期创建入口。
  **例外**：数据分析 agent 使用一个经 CLI 创建的专用超管**服务账号**（非人类使用，如 `agent@cc.local`），
  凭据仅以环境变量注入 MCP server 进程（`mcp/`，stdio 本地运行，不监听端口），不入库、不进对话上下文；
  该账号的全部拉取/上传行为在审计中可归因（`export_jobs.created_by` / `audit_logs.actor_id`），
  吊销方式 = `pocketbase superuser delete`。PRD「全平台唯一超级管理员」指**人类管理员**产品口径。
- SMTP 发信凭据（2026-08 后端改版）：管理员邮件通道（验证/OTP/找回）的 SMTP 在 PB Settings 手工配置（用户方提供发信邮箱）；凭据只存于部署环境，不入库、不进文档、不进审计与日志（同超级管理员初始凭据口径）；下发责任见 §14。
- 生产环境关闭 PocketBase 的调试/开发能力暴露面（如默认 Admin UI 的公网暴露需受控），具体收敛项见 §14。

## 12. 威胁与缓解

依据 PRD §16.1 风险表，转化为实现侧威胁模型：

| 威胁 | 影响 | V1 缓解（实现责任） |
| --- | --- | --- |
| 机构跨租户访问 | 重大数据泄露 | 后端强制 `organization_id` 过滤；自动化越权测试（AC-03）；敏感操作审计 |
| 参与者凭据丢失/重复注册 | 无法报名、去重人数偏高 | V1 不提供找回；允许重新注册；看板按 `participant_id` 去重并注明口径 |
| 二维码被转发 | 无关人员尝试报名/签到/填问卷/培训签到 | 报名需人工审核；签到/问卷需登录 + 审核通过 + 状态/角色校验；培训签到另需存在 approved 聆听者报名 |
| 固定签到二维码截图转发 | 未到场者远程签到 | 仅现场短时开放；管理员核查异常并可撤销（撤销写审计）；动态二维码留后续；培训签到沿用同一口径 |
| 导出文件长期保留 | 敏感文件暴露面增加 | 鉴权访问、不可猜 URL、敏感导出审计、机构权限开关（§10） |
| 无硬删除导致数据积累 | 存储与治理压力 | 归档与状态管理；数据治理与合规政策后续制定 |
| SQLite 单点增长 | 性能/运维限制 | V1 控制规模、索引、每日备份；后续评估迁移 |
| 暴力破解登录 | 账号被接管 | 登录限流（§9）、密码不可逆哈希、参与者侧无凭据重置入口缩小攻击面 |

## 13. 验收标准

与 PRD §14 的映射，安全相关验收须全部通过：

| AC | 场景 | 本文档对应章节 | 验证方式 |
| --- | --- | --- | --- |
| AC-03 | 机构隔离 | §5.2 | 主要列表、详情与导出接口的自动化越权测试全部通过 |

| AC-16 | 规范化导出 | §4 | 普通导出按 `is_sensitive` 标记过滤，数据字典含敏感标记 |
| AC-17 | 敏感导出 | §10 | 开关关闭时管理员不能导出个人信息；开启后需二次确认并审计 |
| AC-18 | 无硬删除 | §8.3 | 产品界面和普通 API 不提供永久删除；归档/作废后历史仍可审计 |

| AC-20 | 幂等提交 | §5.3 | 重试/重复点击不产生重复正式记录 |

补充安全自查项（非 PRD 编号条目，上线前人工核查）：HTTPS 强制与 HTTP 重定向生效；日志中抽查无密码与敏感答案明文；导出下载接口未登录/越权访问被拒绝；审计日志无更新/删除入口；参与者令牌访问管理端 API 被拒绝。
