# ChatCircle 备份与运行隔离修复计划

来源：2026-09-29 用户提供的六项问题；基线 origin/main d7b685b。当前状态：代码已实现，真实数据隔离恢复与邮件SMTP演练已验证，生产尚未部署。实现、隔离验收、生产部署分别记录，实际验收记录见 [备份恢复与告警手册](../../deploy/backup-recovery.md)。

## 修复顺序与验收

1. 移除 backup 对 pb_data 的挂载。PocketBase 内部生成一致性 ZIP，经专用接口下载，服务端仅清理本次生成的归档。验证成功、下载失败、非法名称与并发。
2. backup 不再持有超管密码/token。专用随机密钥只开放快照和备份结果上报，公网网关拒绝 internal 路由；验证它不能访问集合写入、设置、恢复和原生备份管理 API。
3. app、backup、public-web 使用非 root；所有服务只读根目录、no-new-privileges、能力收窄。持久卷迁移必须先备份、停写并只处理实际服务卷，保留可回滚的 UID/GID 记录。
4. 按 app↔backup、app↔public-web、app↔caddy、public-web↔caddy 拆分内部网络。app 独立出口；caddy 保留现有 default 出口及 Empact 的宿主机访问。网络隔离不是 HTTP 路径授权，专用接口仍验证密钥。
5. 按当前约 2 GiB 服务器及实测用量设置内存、CPU、PIDs 上限；预留宿主机与 Empact 运行空间。压力/恢复时观察 OOM 与健康状态，构建不计入运行容器预算。
6. 真备份 ZIP 在隔离网络与独立目录恢复，使用匹配的 HMAC key，禁发短信/邮件，启动后端、公开页和测试网关。检查数据库完整性、业务表计数、上传文件、公开/API/权限以及故障标记、后台告警与恢复解除。

## 发布约束

- 保留主工作区未跟踪文件与 PR #79 的两份保留策略；本分支不擅自覆盖另一任务。
- 共享 Caddy 证书/配置与 Empact 路由必须备份、验证并保留；演练不得绑定正式 80/443、挂载正式 pb_data 或对正式数据执行恢复。
- 本地与隔离测试通过后提交 ready PR。生产切换需要新备份密钥、卷权限迁移和匹配镜像，部署门禁应给出可操作错误；禁止静默退回超管凭据。
- 未配置的站外告警不能写成验收通过；不新增外部通知接收方，不公开密钥、业务数据或归档。

## 回滚

代码回滚使用上一已验证镜像和 Compose，恢复此前记录的卷 UID/GID；备份接口旧版不存在时只能显式使用原受控流程。任何回滚不得删除数据卷、网关证书和未知本地改动。
