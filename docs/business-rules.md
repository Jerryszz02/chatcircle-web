# 业务规则与数据口径

本文保留开发与维护需要的产品约束，替代早期需求稿和阶段计划。协议细节见 [API 契约](api-contracts.md)，集合与状态机见[开发指南](developer-guide.md)，运营操作见[机构教程](org-admin-guide.md)与[平台教程](super-admin-guide.md)。改变这些规则时先确认需求，再同步后端、前端与测试。

## 账号、机构与活动

- 平台管理机构，机构管理单场活动。系列活动拆为多条活动记录；`group_tag` 只是预留信息，不推导额外权限或统计分组。
- 参与者账号跨机构通用；机构管理员只访问所属机构，超管负责机构接入、审批与监管。`speaker/listener` 是每场报名角色，不是账号级权限；同一人可在不同场次选择不同角色。
- 参与者以用户名/手机号与密码登录；注册需用户名、密码和经验证码验证的手机号。验证码登录仅供已有账号；存量账号绑定手机保留原 participant_id，冲突不自动覆盖/合并。
- 管理员使用一次性邀请码注册，邮箱必填；已验证邮箱才能找回密码。超管无自助注册入口，由受控运维创建。
- 服务端同时检查管理员账号和机构是否 active，不能只靠页面隐藏或登录时检查阻止旧 token 继续访问。

## 活动与报名

- 活动代码全局唯一、创建后不可改。总名额为正偶数，两种角色各占一半；不能把名额改得小于已通过人数。
- 活动先草稿，按机构开关直接发布或提交平台审批；驳回要原因，修改后可重提。关闭、归档、下架保留历史，不能随意把终态改回可运营状态。
- 报名窗口与活动结束状态由服务端判断；一人一活动一条报名，无候补。报名申请、审核通过、有效签到是不同口径，实际参与以有效签到计。
- 参与者不自行编辑或取消已提交报名。管理员审核、取消、误判回退和调整角色走状态机；需要原因的操作记录原因与审计，转 approved 在事务内重新核对总名额和角色名额。
- 已有有效签到或活动中配对时，取消报名/改角色返回 `ONSITE_STATE_CONFLICT`；必须先处理现场状态，不能留下角色与签到/配对互相矛盾的数据。
- 每场报名的 `FULL_NAME` 由服务端强制启用、必填、敏感且覆盖两种角色。姓名属于该场报名，不是可用来覆盖其他活动记录的账号别名。历史缺失不伪造补齐。
- 报名字段是带类型、`role_scope` 与 `is_sensitive` 的定义；日期、地点、餐饮、培训时段按活动配置。标准表单版本及历史活动配置保留，不因发布新模板改写旧答案。
- 复制活动/另存机构模板只复制配置、问卷与题目，生成新活动代码和入口 token，不带报名/签到/配对/答卷/审计。复制后须人工调整活动和报名时间；计划签到/问卷时间会清空。机构模板不能直接发布。

## 签到与配对

- 签到须已通过该场报名，且管理员已开放签到；重复扫码幂等。补签、撤销留原因与审计，撤销保留记录。
- 有效签到时服务端按角色分配现场序号，显示 S01/L01 等；号码发出后不复用，旧历史签到不伪造补号。
- 管理员点击开始配对后，按现场序号将两侧等待者配对；迟到者补配不重排已有组。手工调整需原因并原子释放旧组/新建组，保留历史。
- 现场锁定后不再自动改变配对，调整按受控管理员操作执行。首次配对后不能反转活动配对开关；关闭配对的活动不展示等待配对状态。
- 参与者只看到自己的配对状态和搭档在本场填写的姓名，不显示搭档手机号，不可直读全场配对集合。
- 固定二维码不能证明人在现场；转发代签风险见[维护待办](maintenance.md)。

## 问卷、模板与培训

- 一场可有多份问卷。填写资格为已登录、该场报名 approved、角色符合、问卷 open；不强制签到。计划时间仅提示，开放与结束由管理员手动控制。
- 问卷从模板不可变版本物化创建，后续模板更新不影响已有活动问卷。核心锁定题不可被机构改删，稳定题目代码不随标题改动；现有题型不随意变更。
- 一人一问卷一份答卷，草稿到提交是同行状态变化；提交幂等且提交后只读。管理员可作废并留原因/审计，作废不计统计与常规导出，也不自动获得重填资格。
- 当前标准表单包括两份角色报名表和两份 2026-09-24 后测；详见[平台模板说明](super-admin-guide.md#72-标准表单模板)。报名模板不混入活动问卷创建选项，历史版本不删除。
- 聆听者培训独立于活动；签到资格为全平台任意活动存在 approved listener 报名。账号级“已完成培训”依据有效培训签到，撤销后重新计算，跨机构通用；该培训标记用于展示，不作为活动报名门槛。

公开推文 `posts` 独立于活动，仅超管编辑，公开端只展示可见内容；隐藏保留历史。首页成效由公开端服务聚合，不以手工填入的历史数字替代。

## 统计、导出与报告

- 服务人次按有效签到记录计，去重参与人数按有效签到中的 `participant_id` 去重；同一自然人的多个账号不会自动合并，不能把账号数当作已核实的自然人数。撤销签到、作废答卷不能继续计入有效口径。
- 现场问卷完成率分母是角色符合的有效签到者；总体完成率分母是角色符合的 approved 报名者；分子必须与对应人群取交集。零分母返回 null，不能显示假 0% 或超过 100%。
- 性别/年龄分布任一桶不足 5 人时，整维度联合抑制，避免从总数减其他桶反推小样本。姓名/手机号不进入普通聚合图表。
- 机构工作台的历史参与次数按本机构其他活动有效签到去重，截止本场开始与快照时间较早者；未来报名与没有签到的 approved 不计。该辅助聚合与 live-summary 原子主快照分开。
- Realtime 只使快照失效，客户端重拉服务端权威结果；先订阅后取初始快照，断线有提示，重连强制刷新。
- 普通导出排除敏感字段/题目和用户名；敏感判断由服务端统一完成，同码定义不能用非敏感副本覆盖敏感定义。预览不返回真实敏感值，创建时再次判定权限。
- 敏感导出需机构开关（超管豁免机构开关）、明确二次确认和审计；完整手机号、搭档姓名等系统列也受控。机器码、manifest、CSV/XLSX 与行列筛选语义见 API 契约。
- v1 的 13 CSV 导出仍由 MCP 使用。MCP 只取脱敏数据，上传报告强制 draft；工具限制不改变其超管 token 权限。

## 安全、运营与界面

短信当前仅用于身份验证，不发送活动通知或营销短信。心理、情绪、健康等敏感回答不得与身份信息合成为个体画像；新增收集用途须按隐私运营流程确认。

- 常规业务不提供硬删除，采用停用/归档/撤销/作废；敏感操作与业务写同事务审计，日志不可经产品 API 修改。更正、删除、注销与到期处置走[隐私运营流程](privacy-operations.md)。
- 活动/培训个人记录按结束后 2 年管理，账号资料至注销申请处理完成；这不表示有自动清理任务。本机备份保留最近 2 份，异地仍暂缓。
- 参与者流程以手机为主，360px 无横向滚动，微信内置浏览器需真机验收；后台可用桌面布局，但表单标签、键盘操作、错误/加载/空态必须明确，状态不能只靠颜色表达。
- 公开端沿用现有 Empact 风格、导航与页脚，机构/超管端沿用已有样式。CSS token 和实际组件是样式源，不把早期蓝灰 Word 设计稿重新实施到现有页面。
