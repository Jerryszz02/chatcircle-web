# 维护待办与验收边界

接手时先核对这些未闭环事项，再决定后续工作。本文基于 2026-09-30 的仓库整理；没有在本次文档清理中执行生产操作，也不把历史测试结果当作当前线上状态。

## 需要明确范围或补充实现

| 事项 | 当前边界 | 后续完成条件 |
| --- | --- | --- |
| 异地备份 | 本机默认仅最近 2 份；异地目的地暂缓，仓库有 OSS 上传/下载校验脚本 | 明确目的地、预算、恢复目标与权限，再验证定时副本、告警和真实异地恢复；见[异地备份手册](../deploy/offsite-backup.md) |
| 整机故障监控 | 备份监控在同一 ECS 运行，整机停止时无法自行发信 | 确定独立外部监控与通知接收方，实际演练整机不可达告警 |
| 邮件到达确认 | 2026-09-29 备份故障/恢复测试仅有 SMTP 接受记录 | 收件人确认收到两类邮件；管理员验证、OTP 与找回密码也需分别验收 |
| MCP 最小权限 | MCP 保存的 token 仍是超管身份；工具白名单不等于后端授权收窄 | 如要改变，另行设计受限服务身份、导出与报告权限、轮换/撤销及越权测试；见[MCP 手册](../mcp/README.md) |
| 导出文件生命周期与容量 | 已有小时配额和生成并发限制；没有自动清理、单任务内存或导出目录硬预算 | 确认保留期限、下载过期行为与容量阈值后再实现；不要把旧报告建议的 30 天/100 MiB/10 GiB 当作已生效配置 |
| 个人信息到期处理 | 归档、作废和停用保留数据；无业务个人数据自动清理任务 | 按[隐私运营手册](privacy-operations.md)登记请求、定期检查并受控处置，恢复后重放删除/更正台账 |
| 人工账号恢复/合并 | 手机冲突或无法验证旧号时拒绝自动覆盖，尚无完整后台处理流程 | 确认身份核验、授权、关联记录迁移和审计要求后单独实施 |
| 超管会话与现场代签 | 浏览器 token 存 localStorage；固定签到二维码可被转发，未实现 BFF/HttpOnly/MFA 或一次性签到 challenge | 结合现场体验与运维能力评估后立项，不假定现有二维码证明人在现场 |
| 规模与资源 | 并发正确性测试不等于大型活动压力测试；导出/聚合受 SQLite 与单实例资源限制 | 用隔离合成数据验证预计活动峰值、导出内存与延迟；短信 IP 限流/费用预算按场地人数确认 |
| 公安备案展示 | 手册记录主域名已备案，子域名登记范围与页脚公示仍需确认 | 运营核对登记范围，按确认信息更新展示；本次不修改业务页面 |

## 接手时必须重新核验

- 当前 main、成功 CI/E2E、Deploy 目标 SHA、运行容器 revision 和公开页面应能相互对应。Deploy 不自动等待独立 E2E，也不自动回滚，旧 SHA 不能直接绕过快进约束。
- 本机备份检查应同时看调度器、`last_backup.json`、归档完整性、版本侧车与恢复结果；容器 healthy、ZIP 校验或定时器启用都不能单独证明可恢复。
- GitHub 的 required checks 与评审保护属于仓库设置，workflow 文件不能证明这些设置已经启用。
- 360px 微信真机、Chrome/Edge/Safari、键盘操作、手机号真实收码、管理员真实收信需对应发布版本验收。
- 网关与 ECS 由 ChatCircle、Empact 共用，操作前核对在途任务及共享服务依赖。保护现有 SSH、网关站点/证书、数据库和受控配置，不使用全局 Docker 清理解决局部问题。

2026-09-29 的隔离恢复与首次部署证据位置仍保留在[备份恢复手册](../deploy/backup-recovery.md)，它是后续演练的参考，不代替新版本验收。已完成修复的历史经过保留在 Git；新增未闭环事项集中更新本页。
